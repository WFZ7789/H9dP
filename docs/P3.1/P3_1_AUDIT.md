# P3.1 机制审计：我实际看到了什么，又丢掉了什么

> 历史文档：保留当时方案与结果，不作为当前模型路线。命令默认从仓库根目录执行；
> 以后正式训练遵循 [AGENTS.md](../../AGENTS.md)，必须开启 torch.compile，旧 eager 设置仅为历史记录。

## 结论

**本轮模型主要学成了大区域亮温统计的回归器，尚未有效学成核心—云系—环境的空间结构读取器。**

问题不只是窗口大小，也不只是训练轮数：查询在共享更新中明显趋同；三个角色读取相同观测库，缺少实际区域分工；稠密注意力接近均匀；逐像元线性值在建立邻域关系前被大量汇聚，细尺度形态和时间顺序的影响很弱。

这些是本实现、本检查点和本数据上的结论，不是“Transformer 不能估计 dP”，也不是“不用 CNN 就一定失败”。

本次仅新增审计脚本、合成测试及报告，**没有修改模型/训练代码、配置或检查点，没有优化器更新，也没有启动新训练**。

## 二、如果我是这个模型：第一站，我拿到了很多数值，但没有现成的邻域结构

> “每个观测 token 给我四个通道亮温和一个位置。可是这个像元是不是被冷眼墙包围、属于完整环还是散乱斑块，并不在这个 token 里。”

实现对应 `src/h9dp/p3_coverage.py` 的 `_embed`、`CoverageBlock.read`。观测编码是：

```text
e_i = A x_i + p(x_i位置, y_i位置, t_i)
```

其中 `x_i` 是四通道亮温，`A` 是共享线性投影。每次读取，在给定查询和注意力头下，像元得分可写成：

```text
score(q,i) = a_q · brightness_i + b_q · position_encoding_i + constant_q
```

系数可以随样本和查询变化，但单个像元键中没有先计算邻居温差、环状连续性或局部纹理。值投影同样是逐像元线性的。

查询之间的自注意力和后续读取原则上可以间接形成空间比较，因此这不是“数学上绝对不能表达空间结构”。但本实现仅有两层、读取宽泛且查询趋同，实际没有充分形成这种比较。**保留原生像元，并不等于在汇聚前已经建立了原生空间关系。**

### 直接干预证据：破坏细结构，输出几乎不变

在每个小块内部打乱像元，同一个置换用于全部通道、全部帧及掩码：保留各块的联合亮温分布和像元时间轨迹，改变局部邻接与位置配对。

最佳检查点，全部 49 条验证记录；主表采用训练时的 BF16：

| 干预 | RMSE / hPa | 相对正常预测的平均绝对变化 / hPa |
| --- | ---: | ---: |
| 正常 | 14.433 | 0 |
| 4×4 块内打乱 | 14.434 | 0.012 |
| 10×10 块内打乱 | 14.457 | 0.064 |
| 50×50 块内打乱 | 14.685 | 1.023 |
| 全图 500×500 打乱 | 23.858 | 13.954 |
| 移除空间位置编码 | 16.693 | 5.875 |

所以不能说模型完全不看位置：大范围打乱和去位置编码影响明显。更准确的描述是：**它主要依赖大区域的位置和冷暖分布，对本次小尺度结构干预不敏感。**

BF16 量化不是这一现象的充分解释。匹配 FP32 正常前向作为参照时，4×4、10×10 打乱的平均预测变化分别仅 **0.008、0.062 hPa**。FP32 正常与 BF16 正常的平均差异为 0.022 hPa。

这些是对当前模型依赖关系的探针，不证明所有记录都有可识别风眼，也不证明细结构对真实任务没有价值。

## 三、第二站，我的 16 个查询很快开始问同一个问题

> “我最初带着不同的查询和角色标签，但收到的共同更新比我的初始身份大得多。后来大家都在读取相似内容。”

最佳检查点，验证记录上的查询状态：

| 阶段 | 向量 RMS | 查询间平均余弦相似度 |
| --- | ---: | ---: |
| 第一层更新前 | 0.0278 | 0.112 |
| 第一层自注意力后 | 0.2200 | 0.894 |
| 第一层背景读取后 | 0.3642 | 0.959 |
| 第二层背景读取后 | 0.8730 | 0.991 |

第一层自注意力更新本身的 RMS 约 0.220，是初始查询 RMS 的约 **7.9 倍**；背景更新 RMS 约 0.243，且不同查询的背景更新余弦相似度约 **0.995**。第二层自注意力更新几乎完全同向。

### 不是训练后才发生的现象

相同结构以 seed=42 重新初始化，**不训练**，在同一组 3 条训练记录上探测：

- 第一层查询更新前平均余弦约 0.136；
- 第一层自注意力后约 0.935；
- 第一层背景读取后约 **0.972**；
- 第二层背景读取后约 **0.993**。

这说明初始化与共享更新尺度本身就容易造成查询趋同，不应全部归咎于优化后期。

但余弦相似度高不等同于所有信息严格相同：残差仍保留差异，向量 RMS 也不能独立证明唯一因果。本结论还依赖下面的实际读取、角色差值及推理干预证据。没有做“移除共享更新后重训”的因果对照。

## 四、第三站，三个角色没有三个不同的观察范围

> “你叫我中心、云系、环境，但我们都能看同一份固定窗口、同一份背景和全部动态窗口。角色名字并没有给我不同的观测任务。”

代码中的 4/8/4 分组只是可学习角色向量和读出分组。三个组没有各自的空间支持域，没有核心/云系/环境的分区掩码，也没有避免重叠读取的机制。**不是代码漏执行了一个分工，而是设计没有把分工落实为观测约束。**

实际数值：

- 第一层角色亮温差的 RMS 为 **0.0089**；第二层为 **0.0151**，单位均为训练通道标准差归一化后的亮温。
- 同时，各角色读数的跨记录标准差 RMS 约为 0.525、0.552，远大于角色间差值。
- 显式差分分支对回归头第一线性层的跨记录变化贡献 RMS 约 **0.0019**；隐特征分支约 **0.5235**，亮温分支约 **0.2983**。这些是分支预激活统计，不是独立解释度。
- 把显式角色差分输入清零，平均预测变化仅 **0.020 hPa**，RMSE 从 14.433 变为 14.444。

因此，当前“核心—环境差分”主要是名称成立，观测差异和实际利用不足。不能由此推导所有潜在差分信息都完全没用；原始角色输入和隐状态仍可能携带差异。

## 五、第四站，像元数量在替我分配注意力

> “我没有学会非常明确地聚焦某个结构。哪个来源给我的像元多，哪个来源就自然占据多数权重。”

每帧有 20,073 个读取位置；六帧分别进行稠密读取，并非一次对六帧联合归一化 120,438 个权重。

| 来源 | 每帧位置数 | 完全均匀时的权重 | 最佳检查点第一层实际权重，约 |
| --- | ---: | ---: | ---: |
| 全窗背景 | 256 | 1.28% | 1.44% |
| 固定中心 | 16,641 | 82.90% | 81.91% |
| 动态原生 | 2,500 | 12.45% | 13.12% |
| 动态双线性 | 676 | 3.37% | 3.54% |

实际第一层来源比例非常接近纯计数先验。不能把固定窗口占 82% 直接解释成模型“认定核心最重要”。

流式精确注意力统计还显示：

- 第一层注意力相对均匀分布的平均 KL 仅 **0.0516 nats**；第二层 **0.0979 nats**。
- 指数熵等效支持占有效位置数量的比例约为 **95.0%、91.0%**。
- 固定窗口内部的平均 KL 也仅为 0.0464、0.0611 nats。

这不是权重完全相等，但远没有形成强烈的稀疏聚焦。若一个局部结构只占一两个百分点的像元，而读取又接近均匀，它对整体摘要的影响就很容易被稀释；这只是机制说明，不是对实际风眼大小的标注结论。

### 把稠密读取直接改成均匀平均会怎样

| 集合/检查点 | 正常 RMSE | 均匀稠密读取 RMSE |
| --- | ---: | ---: |
| 最佳点训练集 | 16.543 | 16.637 |
| 最佳点验证集 | 14.433 | 14.557 |
| 最终点验证集 | 14.947 | 15.605 |

“均匀读取”只替换 `CoverageBlock.read` 中的稠密观测权重，**仍保留背景条件化、自注意力、路由、投影和回归头**，不能称为完整的无注意力模型。最佳点验证预测平均改变 1.191 hPa，不是完全不变；但总体精度非常接近，说明当前稠密注意力相对这种均匀读法的额外收益很弱。

## 六、第五站，我把六帧更多当成了一组观测，而不是明显利用演变顺序

代码在学习式隐特征路径中，对六帧读取结果执行 `.mean(1)`；数值旁路仍保留各帧读数，真实分钟偏移也参与计算，因此时间信息没有从整个模型中完全删除。

实际干预：

| 干预 | RMSE / hPa | 平均预测变化 / hPa |
| --- | ---: | ---: |
| 正常 | 14.433 | 0 |
| 影像帧顺序反转，时间输入不变 | 14.416 | 0.093 |
| 六帧都替换为最新帧 | 14.383 | 1.293 |
| 所有分钟偏移设为零 | 14.917 | 1.879 |

模型对时间数值有依赖，但对本次影像顺序干预的响应很弱。最新帧重复的单次 RMSE 略好，不构成“单帧一定优于六帧”的结论；这里只说明当前六帧设计没有展示出预期的顺序信息收益。

FP32 匹配精度的反序探针平均变化仍仅为 0.092 hPa，不是 BF16 才出现的现象。

## 七、第六站，回归头接到的主要仍是少数共同冷暖因子

最佳点验证集送入回归头的 456 维输入，按原始特征尺度作 PCA：

- 第一主成分占跨记录方差 **89.6%**；
- 前两个主成分已超过 95%。

PCA 受尺度、重复特征和样本数影响，不能把这一结果当作“模型只有两维信息”或单独当成失败证据。但它与角色趋同、亮温近似平均的结果一致。

预测与全图各通道平均亮温的相关系数约为 **-0.82 至 -0.86**；真实 dP 与这些均值的相关系数仅约 **-0.50 至 -0.55**。当前模型对大区域冷暖统计的依赖比任务目标本身更强。

同时，移除全部亮温数值旁路会使 RMSE 升至 17.464，移除隐特征输入会升至 18.075。**两个分支都在工作，不是只接通了一条线；但它们很大程度上在重复编码相近的共同统计。** 这也是受限的推理干预，不能当作分支独立重训的比较。

最终输出标准差仅 11.825，而标签标准差为 20.076；弱 dP 高估、强 dP 低估。输出函数 `softplus` 没有上限，在 50–90 hPa 区间导数几乎为 1，不能把幅度收缩归咎于硬截断或饱和上限。

## 八、路由梯度并没有断：排除一个容易讲错的解释

在同一组 3 条训练记录上，保留完全相同的前向数值，只分离部分反向路径：

| 探针 | 第一层路由 xy 梯度 RMS | 第二层路由 xy 梯度 RMS |
| --- | ---: | ---: |
| 完整反向 | 2.683e-3 | 1.260e-4 |
| 断开动态亮温反向，保留位置编码路径 | 6.915e-4 | 5.107e-5 |
| 断开局部位置编码反向，保留亮温采样路径 | 2.584e-3 | 1.069e-4 |

三组前向预测最大差异为 0。说明梯度确实通过双线性亮温采样传回，**不是只有位置编码在提供梯度，更不是路由断梯度**。

这些梯度范数不是可相加的贡献百分比，第一层还影响后续查询。第一、二层路由的像元位移尺度不同，也不能仅凭第二层梯度小就判定故障。

已有检查点读取诊断中，最佳点读取中心在样本间的标准差仅约 0.4–0.5 像元，固定路由的 RMSE 为 14.552，接近正常 14.433。更合理的判断是：**梯度存在，但当前观测/汇聚方式给“寻找不同局部结构”的任务收益很弱，路由没有学到明显的逐样本搜索行为。**

## 九、数据、数值与评价：发现了什么，未证明什么

已核对：

- 数据/代码指纹匹配，模型正常重算结果与训练预测一致。
- 四通道顺序为 B08/B09/B10/B16，使用训练记录归一化及训练标签归一化。
- 索引中的六帧时间偏移严格递增；实际审计读取的公共有效像元比例为 1，没有用大批无效填充值解释平均化。
- FP32 与 BF16 的正常预测差异很小；小尺度打乱和时间反序的不敏感在 FP32 中复现。
- 所有参数均未累积审计梯度，检查点文件哈希不变；没有新训练进程。

保留的限制：

- 训练有 152 个帧次、验证有 26 个帧次晚于标签时刻；当前不是严格因果实时预报协议。
- 训练/验证共享 9 个台风和 4 个原始帧组；这影响泛化评价可信度，不是这次训练欠拟合的充分解释。
- 本次未独立用外部物理基准重新验证全部 HSD 定标，也不能证明标签无噪声。
- 不能把反复审计的 49 条验证记录称为新的盲测集；不根据其中微小 RMSE 差异挑新架构。

## 十、责任定位与下一步边界

### 已证实的现象

查询趋同、角色读数近似重复、稠密权重接近均匀、细尺度打乱与反序响应很弱、训练误差仍高。这些共同支持表示和读取退化，而不只是过拟合。

### 最有依据的机制解释

```text
很小的查询/角色身份
    + 更大的共享自注意力和背景更新
    → 查询共同分量主导

无实际区域约束的角色 + 按像元数量竞争的共同观测库
    → 角色分工弱，固定大窗口获得计数优势

逐像元线性值 + 宽泛汇聚，局部关系尚未建立
    → 近似大区域亮温摘要，细结构和时间顺序利用弱

多个分支重复同一类共同统计
    → 回归头难以刻画强弱两端，输出向中间收缩
```

这是有多项探针支持的机制链，不是每条箭头都已通过独立重训证明唯一因果。

**设计上的主要失误是我把“观测可访问”当成了“关系可辨认”，又把“查询有角色名字”当成了“查询已有观测分工”。增加窗口修复了前者的覆盖，却没有修复后者的表示和优化。**

下一版不能仅继续增加窗口、层数或训练轮数。若要做单变量对照，应先落实：

1. 查询身份与共享更新的尺度可控，但不预先声称单独门控就能解决全部问题。
2. 核心候选、云系、环境拥有可解释且确实不同的观测支持，来源竞争不由像元数量自动决定。
3. 在大量空间汇聚前，有路径表达局部相对关系；维持无前置 CNN 约束也不能退化为只给像元贴位置标签后平均。
4. 先检验读取特征能否区分亮温直方图相同、空间组织不同的合成图案，再讨论一次预算一致的完整训练对照；这种辨识测试不替代真实任务精度验收。

**本次审计到此止于定位，不修改权重、不启动 P3.2，也不进入多 seed 复验。**
