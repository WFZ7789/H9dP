# V1 发布分析：`inference/best` 的能力边界

**状态：已完成，2026-11-22。** 固定种子 1，546 条真实 Himawari 记录的记录级五折折外结果，
以及 `inference/` C++ 推理件（[C++20 推理库](CPP_INFERENCE.md)）的验收数据。
本文是发布说明中的**分析部分**，模型结论和验收口径分别见 [V1 实验报告](README.md)
和 [评估口径](../EVALUATION.md)；本文不重复实验协议，只解读结论、误差结构和发布风险。

本文的对比表、分箱表和尾部统计由 `scripts/v1_release_analysis.py` 从已发布的折外预测复算，
**没有重新拟合、没有重新生成预测**。复算产物位于
`/mnt/data/H9dP/runs/v1/rotation_seed1/release_analysis.json`。

## 组会式摘要

目标是**只给六帧 Himawari 云图，估计台风的降压 dP（hPa）**，也就是环境气压与中心气压之差。
模型看不到任何气压计，也看不到地面窗区通道：B08/B09/B10 是 6.2/6.9/7.3 µm 水汽通道，
B16 是 13.3 µm，四个波段都在看高层云和上对流层水汽。**它实际学到的是一个"台风组织度指标"**：
眼清不清楚、眼墙环有多强、CDO 有多冷多不对称、云系转得多快。

这个定位决定了两件事：模型在眼区清晰的记录上明显更好（Good 6.93 hPa 对 Poor 10.50 hPa），
而在"不像台风"和"极端强"的两端都会向中间收缩（见[分箱](#3-误差是有结构的压缩)）。
核质量、特征族消融和"为什么有效"的机制证据见[Why it works](WHY_IT_WORKS.md)。
发布件把它做成了不需要 GPU、直接读 HSD/DAT 的 C++20 库，移植误差 6×10⁻⁶ hPa，
单条 125 ms，其中 31% 是核回归、69% 是解码与极坐标采样。

## 1. 发布内容

| 项 | 内容 |
|---|---|
| 模型 | V1，全体折外 RMSE **8.901 hPa**（MAE 6.830，偏差 −0.015） |
| 推理件 | `inference/inference_best.{hpp,cpp}`、`hsd.cpp`、`v1_features.cpp`、`main.cpp`，C++20 静态库 + CLI |
| 权重 | `fold0..4.v1m`，五折等权平均；每折 **436 个对偶系数**，单折 32.0 MB，合计约 160 MB |
| 输入 | 每帧四波段 DAT（B08/B09/B10/B16，`.DAT`/`.gz`/`.bz2`），1–6 帧，外加中心经纬度 |
| 输出 | dP（hPa）标量；`predict()` 为 `const`，可多线程并发 |
| 依赖 | 无 GPU、无 Python 运行时；zlib 必需，BZip2 可选 |

模型文件体积值得说明：它不是几百万参数的神经网络，而是**对 436 条训练记录的核展开**
加逐特征组的样条和线性项。所以体积随训练记录数增长，推理代价是每条记录 O(记录数 × 2060 维)，
这也是后面时延分析里回归部分固定占 39 ms 的原因。

## 2. "第一名"这个说法不成立

546 条记录的全体 RMSE 排序是 8.901（V1）到 12.195（EC1）。但对这 546 条逐记录预测做
**配对 bootstrap**（MSE 差，5000 次重采样，种子 1）后，前十名里只有三组能和 V1 分开：

| 模型 | RMSE | ΔRMSE | MSE 差 95% 区间（hPa²） | 与 V1 可分 | 误差相关 |
|---|---:|---:|---|---:|---:|
| **V1** | **8.901** | — | — | — | 1.000 |
| A1 | 8.962 | +0.060 | [−2.2, +4.4] | 否 | 0.981 |
| R1 | 8.963 | +0.061 | [−7.2, +9.3] | 否 | 0.833 |
| E1 | 9.028 | +0.126 | [−1.8, +6.2] | 否 | 0.957 |
| C1 | 9.112 | +0.211 | [−3.1, +10.8] | 否 | 0.865 |
| F1 | 9.197 | +0.295 | [−1.5, +12.0] | 否 | 0.902 |
| H1 | 9.271 | +0.369 | [−0.2, +13.4] | 否 | 0.908 |
| D1 | 9.798 | +0.897 | [+8.4, +25.3] | 是 | 0.863 |
| W1 | 9.807 | +0.906 | [+8.9, +24.9] | 是 | 0.857 |
| EC1 | 12.195 | +3.293 | [+53.4, +86.9] | 是 | 0.672 |

更直接的量级对照：**同一份 V1 的五折 RMSE 是 7.605 / 9.368 / 9.134 / 9.979 / 8.232**，
跨度 2.4 hPa；而排行榜前六名总共只差 0.37 hPa。折间噪声比选手差距大约六倍。

因此发布口径应为**"六个统计上等价的模型并列第一组，V1 是其中误差最低的一个"**，
而不是"V1 最优 0.06 hPa"。区间本身也偏窄：546 条记录来自有限的风暴和同一系列卫星，
同气旋的多条记录高度冗余，按记录独立重采样会低估真实不确定性，真实区间只会更宽。

## 3. 误差是有结构的压缩

按目标 dP 分箱（V1 折外误差）：

| 目标 dP（hPa） | 记录 | RMSE | MAE | 偏差 |
|---|---:|---:|---:|---:|
| 0–30 | 5 | 19.141 | 16.617 | **+15.312** |
| 30–40 | 14 | 14.012 | 11.717 | +11.049 |
| 40–50 | 48 | 10.266 | 8.160 | +4.442 |
| 50–60 | 86 | 7.442 | 5.996 | +2.830 |
| 60–80 | 191 | 8.439 | 6.317 | +0.072 |
| ≥80 | 202 | 8.691 | 6.774 | **−3.515** |

两端都向中间收：弱系统被高估，超强系统被低估到 −3.5 hPa。原因在数据本身——
562 条 MOTIS 记录里 **402 条 dP ≥ 60**，而 dP < 40 只有 19 条（本次评估集内），
损失又是等权 MSE，模型学到的第一件事就是"这是个台风，答 80 多"。

误差尾部也不软：

| 统计量 | 值（hPa） |
|---|---:|
| 绝对误差中位数 | 5.46 |
| 绝对误差 p90 | 14.30 |
| 绝对误差最大 | 38.79 |

最坏一条目标 64.3 hPa 被预测为 103.1 hPa。**结论：单条裸输出不能直接当业务值用**，
至少要和五折分歧一起给出。Sinlaku 十分钟序列上五折标准差均值 2.94、最大 9.17 hPa
（[展板](SINLAKU_POSTER_20261122.md)），这个分歧量级和上面尾部误差是自洽的。

## 4. 十个模型其实只有两三种误差结构

与 V1 误差的相关系数：A1 **0.981**、E1 0.957、H1 0.908、F1 0.902、C1 0.865、D1 0.863、
W1 0.857、R1 0.833、EC1 0.672。A1 和 V1 名义上是不同架构，误差几乎完全重合，
说明它们其实是对同一批描述子做了两种拟合。

用同一批折外预测做等权平均（**事后计算，未发布，偏乐观，不能当作模型结论**）：

| 组合 | 全体 RMSE |
|---|---:|
| V1 单独 | 8.901 |
| V1 + A1 | 8.870 |
| V1 + A1 + R1 | 8.548 |
| 前五名等权 | **8.503** |
| 全部十个等权 | 8.584 |

它唯一的用处是给一句判断：**这条特征路线的天花板在 8 hPa 附近**。继续刷变体拿不到新信息，
要往下走必须换信息源或换标签，而不是再调一次核。

## 5. 移植精确，但验收不等于泛化

| 验收项 | 实测 | 结论 |
|---|---|---|
| 546 条缓存描述子 OOF RMSE 差（C++−Python） | 3.7×10⁻⁸ hPa，逐条最大 6.2×10⁻⁶ hPa | 移植精确 |
| 329 条本地 DAT 端到端 OOF RMSE 差 | 1.6×10⁻⁸ hPa（C++ RMSE 8.9349） | 移植精确 |
| 总耗时比（C++ 读 DAT / Python 仅预处理） | 1.125×（41.48 s / 36.86 s） | 达标 |

6×10⁻⁶ hPa 只有一个含义：差值来自 FP32/FP64 舍入，实现与 Python 同源。**但这只证明代码等价。**
两项验收用的是同一批折外预测和同一批折号，不含任何新样本；DAT 端到端那 329 条只覆盖 546 条中的
60%，且偏向强台风（其中 238 条 dP ≥ 60、仅 15 条 dP < 40），2016–2019 全盘记录未纳入。
**不要把"通过验收"读成"泛化更好"。**

## 6. 时延预算：瓶颈不在模型

发布验收报告的中位数是 124.7 ms/条。把 `--features` 路径（只走已缓存描述子的回归，
不解码 DAT）单独计时，可以拆开：

| 组成 | 每条耗时 | 占 124.7 ms |
|---|---:|---:|
| 5 折核回归（436 对偶 × 5 折） | 38.9 ms | 31% |
| DAT 解压 + 定标 + 裁切 + 极坐标采样 | 约 86 ms | 69% |
| 模型加载（页缓存已热） | 约 83 ms，一次性 | 不计入单条 |

所以想降到 30 ms 级，该动的是解码和采样（R304 2 km 瓦片、减少采样点、按需少折），
不是模型本身。绝对量级上 125 ms 对十分钟一次的观测来说完全够用，这一项不构成发布障碍。

## 7. 局限（发布必须同时说明）

1. **目标是分析量，不是实测。** dP 来自 MOTIS；中心气压由 `round(POCI − dP, 1)` 派生。
   8.9 hPa 里有一份标签自身的分析不确定性，不能直接对标"实测中心气压准不准"。
2. **评估集是开发集。** 546 条不是独立观测集；记录级五折与未来的业务运行之间还隔着真实泛化这一步。
3. **DAT 核对覆盖 60%**，且偏向强台风；2016–2019 全盘记录未纳入端口核对。
4. **C++ 只承担已训练模型的推理**，Python 的 GPU 银行/GP 训练流程没有被替换。
5. **分箱小样本**：dP < 30 只有 5 条，那一行 RMSE 19.1 的统计意义有限，读作"方向明确、数值不可靠"。

## 8. 下一步（按优先级）

1. **停止增加同族变体。** 前六名统计不可分、误差相关 0.9 以上，特征族已饱和。
2. **换评估数据。** 用已收集的实测（JMA 站点与投送仪，dP > 30 目标；1,769 条强压差配对）
   做独立观测检验，这是唯一能把 8.9 变成"可信 8.9"的动作，也是[实测集准则](../data/OBSERVATION_POLICY.md)的要求。
3. **补两端标签。** dP < 40 只有 19 条、≥80 有 202 条，压缩偏差是数据缺口的直接后果，后处理改不掉。
4. **发布接口带不确定性。** 五折分歧已是可用的代理量，不要只发标量。
5. **要低延迟就砍解码。** 69% 时间在解码与采样，模型只占 39 ms。
