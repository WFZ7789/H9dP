# M1 测试阶段结果

## 1. 状态与结论

**已完成。** 2026-11-13 至 2026-11-14 UTC 执行了开发阶段（184 条训练 / 46 条留出）和最终阶段（230 条训练 / 49 条验证）。正式训练均启用 `torch.compile` 与 CUDA BF16，未回退 eager。

结论：

1. 五个中间参数都可从当前六帧影像学到优于训练均值基线的信号，E3（Eye size）最稳定，E4（`B33 dT tr.`）最弱。
2. 但把预测参数送入 M5 后，**组合精度没有达到预先设定的成功条件：未优于同协议、同预算的直接 dP 回归对照**。
3. 最终 49 条：M5 组合 RMSE **14.56 hPa**，直接回归对照 **12.95 hPa**，训练均值基线 **20.49 hPa**。
4. 这不否定“中间监督”方向本身，但说明在当前参数精度和数据量下，线性 M5 会放大参数误差。M1 测试版保留为诊断基线，不进入部署候选。

仅运行 seed 42、单一划分；49 条是项目既有验证集，不是从未使用的盲测集。本报告的所有 49 条结果均在协议冻结后只评估一次。

### 2.1 协议修订

首次 dev 使用计划中的 `lr=1e-3`、`weight_decay=1e-4`、`patience=20`。结果 E1 最佳轮次只有第 1 轮，M5 组合为 17.44 hPa，而对照直接回归为 8.01 hPa；直接回归在更高学习率下明显更好。该轮只作为探索证据保留在 `dev_lr1e-3/`。

在查看 49 条之前，将开发协议修订为 `lr=3e-4`、`weight_decay=1e-3`、`lr_patience=10`、`early_stopping_patience=25`，重跑 dev。最终阶段只使用修订后 dev 选出的轮次：

| 模型 | 最终训练轮数（dev 最佳轮） |
|---|---:|
| E1 B24 | 3 |
| E2 B36 | 5 |
| E3 Eye size | 34 |
| E4 B33 trunc. | 9 |
| E5 CDO | 27 |
| 直接回归对照 | 25 |

对照与专家使用相同学习率、权重衰减和训练轮次选择规则。对照在 `lr=1e-3` 时 dev 为 8.01 hPa，因此这里对 M1 的否定结论并不依赖“对照被削弱”的解释。

## 4. 模型与成本

| 组件 | 参数 | 说明 |
|---|---:|---|
| 单个 E | 17,285 | 六帧共享空间编码，1 个标量输出 |
| 五个 E | 86,425 | 权重、优化器、检查点完全独立 |
| M5 | 5 个系数 | 训练侧 OLS，拟合后冻结 |
| 直接回归对照 | 88,353 | 相同读出结构，更宽通道，端到端 dP |

M5：

```text
s = (35 - min(T_CDO, -50)) / 100
dP = b + s * (a1*B24 + a2*B36 + a3*EyeSize + a4*B33trunc)
```

E3 使用 `sigmoid * 1/sqrt(8)`，E4 使用 softplus 保证非负；E1/E2/E5 为线性输出。模型输出始终为物理单位，损失按训练目标标准差归一化。

实际资源与耗时（final，230 条、batch 4、58 步/轮）：

| 项目 | 数值 |
|---|---|
| 编译冷启动（首个训练步，含编译） | E1 1.63 s，对照 0.70 s |
| 后续同形状模型 | 0.01–0.31 s（复用 Inductor 磁盘缓存） |
| 稳态每轮 | 2.77–3.14 s |
| 峰值显存（分配） | 专家 910 MB，对照 1,595 MB |
| final 阶段总墙钟 | 约 5.5 分钟（不含数据准备） |
| dev 修订阶段总墙钟 | 约 13 分钟 |

首个 dev 运行的冷编译为 12.79 s。以上是显存分配峰值，不是整卡占用；未使用 activation checkpointing，峰值已实测且远低于 16 GB。

| E2 | B36 dT (°C) | 5 | 2.253 | 1.773 | +0.326 | 2.435 | 3.805 |

## 7. 误差分析

### 7.1 系数放大

M5 对参数误差的近似敏感度（`s≈0.95`）：E1 约 3.0 hPa/°C，E2 约 5.4 hPa/°C，E4 约 3.2 hPa/单位，E3 约 73 hPa/单位，E5 通过缩放约 0.6 hPa/°C。46 条上 oracle 为 7.70，而单独替换 E2/E4 就升至 15.6/15.9，说明参数误差被线性组合放大。

### 7.2 预测方差收缩

49 条上的参数预测分布与 230 条真实参数分布对比：

| 参数 | 预测均值 | 预测标准差 | 真实均值 | 真实标准差 |
|---|---:|---:|---:|---:|
| B24 dT | 4.882 | 2.411 | 3.188 | 4.237 |
| B36 dT | 4.705 | 2.002 | 3.069 | 4.167 |
| Eye size | 0.195 | 0.091 | 0.228 | 0.108 |
| B33 trunc. | 1.380 | 3.051 | 4.072 | 7.144 |
| T CDO | -64.189 | 9.440 | -63.576 | 9.758 |

B24/B36/B33 的预测标准差明显小于真实分布，呈现回归到均值的收缩。M5 是线性映射，输入方差收缩会直接压低 dP 方差：49 条预测 dP 标准差为 15.95，真实为 20.08。这是“参数 RMSE 尚可、组合 dP 却差”的主要原因之一。

### 7.3 无法拆分的误差来源

49 条没有旧版完整参数，因此不能把最终误差分解为“E 参数误差”与“M5 映射误差”。M5 只使用 2020–2025 年旧版参数校准，而验证全部是 2026 年；E5 的预测均值与训练分布接近，但 E1/E2/E4 存在明显分布差异。该差异可能来自年份、观测条件或模型收缩，现有数据无法区分。

## 8. 局限与判定

- 只运行 seed 42；未做多种子稳定性评估。
- 46 条 dev 留出用于两轮超参选择和早停，不能视为无偏测试；49 条最终验证在协议冻结后只评估一次。
- 按 record 划分，同一气旋的不同记录可跨 fold，不能宣称跨气旋泛化。
- 49 条全部为 2026 年，且无旧版参数标签；无法验证参数精度，也无法做 oracle 组合。
- M5 是线性映射，只用真实训练参数拟合；未用预测参数的 OOF 分布重新校准。
- E4 的 `B33 dT tr.` 是受云遮挡影响的修正量，当前四个 Himawari 波段可能不足以可靠反演；这是可观测性问题，不是简单调参问题。
- 直接回归对照在同预算、同数据下更好；M1 的当前实现**未通过**测试阶段成功条件。

因此：**M1 测试版判定为未达组合目标。** 保留其参数专家与诊断工具，不把 M5 组合作为候选模型，也不在 49 条上继续调参。

## 10. 后续建议

若继续该方向，优先级应是**降低 M5 对参数误差的放大**，而不是盲目扩大网络：

1. 用训练侧 OOF 预测校准 M5，使映射适配“预测参数”的收缩分布；必须只用训练侧 OOF，不能使用 49 条标签。
2. 对 E1/E2/E4 增加更强的正则或数据增强，先验证参数留出精度能否接近 1 K 量级；否则线性组合难以优于直接回归。
3. 把 `B33 dT tr.` 视为可观测性候选：先做“该参数是否可由当前四波段恢复”的独立检验，失败则从 M5 移除，而不是继续强迫 E4 拟合。
4. 若仍要保留组合，考虑非线性或残差式 M，但必须与直接回归在同一划分、同一预算下比较。
5. 任何进一步评估应使用新的留出年份或重新预注册的协议，避免在 49 条上反复选择。
